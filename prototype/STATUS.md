## 1. 这一版是什么

一块悬空的 10m 长板，4 条轨，没有凹槽、没有边框、没有底座。**没有键型、判定、shift 动画、谱面。**

- **台面**：1092 × 10000 × 12mm 的整板，圆角 + 2mm 倒角。
- **4 轨**：每轨 230mm，分割线 1.6mm 暗线（不是槽，不是导轨）。
- **判定带**：横跨 4 轨的一条冷白光带（柔光 + 芯线），静态。
- **剖切**：近端整面 + 右侧靠玩家 2.4m 的一段敞开；内部有承力底板、中层甲板、纵筋、横梁；切面有 6mm 倒角框与断面端头。
- **浮空显示**：曲名 / 分数 / 物量，世界固定，只有字和一条黄铜细线。
- **材质**：黑阳极铝（拉丝）+ 机加工铝 + 腔体暗色。陶瓷 / 玻璃 / 冰 / 黄铜仍在材质库里，等 Step 2 的键型。
- **环境**：程序化 PMREM 暗房 + 灯带；主光 + 轮廓光 + 台灯 + 10m 跑道补光。
- **背景**：暗房 + 1m 网格地面，雾收在 9–30m。

## 5. 已知问题

1. **没做阴影**。4.6 要求接触阴影至少 SSAO 级；three 的 `EffectComposer` 不能直接用于 WebXR 双目，留到 Step 2 和键的落地阴影一起解决。
2. **10m 进深下，远端只剩一条线**。分割线在远处会并到一起；如果实际读不出 4 轨，要么加宽轨、要么在远端加一点明度差，要么靠「note 从哪条线出来」来读。
3. **判定带的亮度很难调**。台面本身有台灯形成的高光池，additive 的判定带叠上去容易过曝；现在压到 0.3 / 0.16，偏暗但不再糊成白条。VR 里要再确认。
4. **浮空显示默认位置的依据**：右前方 2.6m、台面上方 0.1m，理由是「看轨道时它就在视野上沿」。如果还是瞄不到，面板里直接拖 X/Y/Z，把数字告诉我。
5. **台面悬空、没有支撑**。目前是刻意的「仪器」处理；如果 VR 里觉得无根，加一根竖梁。
6. **剖切只剩结构，没有零件**。轴承、走线、检修灯带都删了；如果嫌空，可以加回一层。
7. **背景很素**。只有暗房 + 网格 + 渐变；3D 演出属于单曲异象，Step 1 不做。
8. **参数变更是全量重建**。拖滑块会重建台面几何（材质与贴图复用）。
9. **`ExtrudeGeometry` 的 bevel 会向两端各多长一段**，已修；顶板厚度按 `plateThickness` 精确落位。

## 8. 第四版：材质细化（冰 / 玻璃 / 瓷）

这一版只动材质与一块 dev 用的实验台，不改台面尺寸。

### 做了什么

| 材质 | 表面行为 |
| --- | --- |
| **冰** | Worley 晶面法线（40 个细胞）+ 透明混合；基色 `0xb8d6e4`、`opacity 0.42`、`clearcoat 0.55`、`envMapIntensity 0.9` |
| **清玻璃** | 透明混合；基色 `0x9fc0d4`、`opacity 0.32`、`clearcoat 0.6`、`envMapIntensity 1.0`、波纹法线 1.2；管内有光带 |
| **烟熏玻璃** | 同一条波纹管线，更暗、更不透明 |
| **暗瓷** | 釉面低频起伏（法线 0.22）+ 柔和的粗糙度斑；`clearcoat 1.0` |
| **黄铜** | 未改（金属度 1、粗糙度 0.26） |

**阴影**：只让台灯投影，一张 1024² 的 `PCFSoftShadowMap`，不做级联、不开别的光源。样品与台面都参与（`castShadow` / `receiveShadow`）。这是「最简单的方式」，透明物体目前投的是实心影。

- 所有法线贴图都是**程序化高度场求导**得到，可平铺；冰用 Worley（细胞），玻璃用 value noise。
- 粗糙度斑是「被手摸过」的软斑块，不是划痕 —— 对齐 `parallax-idea.md` 4.6 的「使用痕迹」。
- 高度场先归一化再求导，否则距离场的斜率太小，法线几乎是平的（这一版修掉的坑）。

### 怎么看

- **材质实验台**：dev 下默认显示，浮在正前方 0.7m。四件样品自转，上方一盏检验灯。
- 关掉：`?lab=0`，或调试面板「材质实验台 → 显示样品」。

### 已知限制

1. **`transmission` 试过，撤了**。它在「均匀亮台面」这个背景下会变成一块发白的板：亮处透过去是亮的，暗处又没东西可透，结果既不透明也不像玻璃。现在回到透明混合 —— 背后的轨线、台面纹理都能看见。代价是没有真实折射（线不会被折弯）。要折射的话，得先把玻璃放到有对比的背景前，或者等 Step 2 有 note 穿过管身时再试。
2. **透明物体投实心影**。玻璃与冰的阴影和陶瓷一样黑；真实情况应该是透光的浅影。简单做法的代价。
3. **「太白」与「不透明」是同一个旋钮的两端**。基色压深 → 白没了，但透射也没了；基色提亮 → 透，但白。最后选择透明混合 + 冷色基色：透光靠 `opacity`，颜色靠 `color`。两个旋钮分别控制，不再互相打架。
4. **阴影只有一盏灯、一张 1024 图**，覆盖台面前 ~3m；远端没有阴影。
5. **没有环境光遮蔽**，样品之间的遮挡关系靠明暗与法线。
6. **贴图是各向同性的**：玻璃波纹没有方向性，冰的晶面是随机细胞，不是沿锥面生长的棱 —— 近看能看出来。
7. 实验台在 dev 下默认显示，正式玩的时候要 `?lab=0`（或等 Step 2 有真实键后删掉）。

## 9. 键型造型（Step 1 补完，2026-10-17）

四种键型已经做出来了，**只有造型，没有判定 / 生成 / 回收**。

| 键型 | 造型 | 尺寸（米） | 材质 |
| --- | --- | --- | --- |
| **hit** | 横跨轨道的厚条 | 0.21 × 0.055 × 0.075 | 陶瓷（倒角、釉面）：青釉 / 无釉 / 赤釉 |
| **drag** | 横置细条，三枚一串 | 0.195 × 0.011 × 0.022 | 冰（`iceBar`）+ 加法辉光片 |
| **hold** | 贴在轨道上的平片 + 片内亮带 | 0.21（= 轨宽）× 0.006 × 1.2，亮带 55% | 清玻璃 + 发光芯 |
| **arc** | 拱形玻璃管 + 发光芯 + 两层泛光 | 管半径 0.018，拱高 0.34 | 青 / 赤玻璃 + 同色光带 + fresnel 加法壳 |

- 泛光不是后处理 bloom：是包在管外的两层加法壳，用菲涅耳（`1 - |N·V|`）控制强度，所以只在轮廓附近亮。
- arc 的泛光有轻微呼吸（0.4 ± 0.1），只是让「光」看得出是活的，不是节奏。
- drag 不再用锥形：俯视下锥形会被压成一个点，横条才能读出「一串」；辉光是一张水平加法渐变片（壳层会在冰条两端亮成两个点）。
- 位置：hit 三枚并排在 1–3 轨（z ≈ 近端 −0.55），drag 三枚在 4 轨近端（z ≈ −0.62…−0.91），hold 在 4 轨 z ≈ −1.75（长 1.2），arc 两条并排在 2 / 3 轨、z ≈ −1.35…−2.65。

**还没做**：判定输入、手感反馈、生成 / 回收、arc 跟随、端面切角冗余。这些是 Step 2 的主体。

## 10. 手别配色（2026-10-17）

针对「arc 颜色不明显 / hit 与台面对比太低」，把青 / 赤两套手别色落成材质。

| 载体 | 左手 | 右手 | 中性 |
| --- | --- | --- | --- |
| 陶瓷 hit（釉） | 青釉 `#1b363c` | 赤釉 `#431e24` | 无釉 `#5a6067` |
| 玻璃 arc（管壁） | 青玻璃 `#2e6b76` | 赤玻璃 `#743038` | 清玻璃 `#9fc0d4`（hold 用） |
| 管内光带 | `#8ff0ff` | `#ff8fa3` | `#c6e9ff` |
| 泛光壳 / 光斑 | `#2fc4d8` | `#ef2a45` | `#bfefff`（drag / hold 中性光斑） |

- 色值在 `src/materials/palette.ts` 一处定义，材质库与泛光着色器都从这里取；改色只改一个文件。
- **同一个色相有两种取值**：台面的灯很亮（key 2.8 + lamp 30），釉色必须压暗才不会被打成粉彩；玻璃是透明混合，颜色会被洗淡一半，所以玻璃取值更亮更饱和（`glaze` vs `glass`）。
- 中性 hit 用**亮灰瓷**：够亮、能在暗台面上立住，但明度里不带任何色相倾向，不会被误读成某只手。
- 三枚 hit 同一排、同尺寸、同一 z：手别的差别只剩颜色，不掺造型差别，方便直接比色。
- 两条 arc 并排（2 / 3 轨），管壁 / 管芯 / 泛光三层同一色相——玻璃一透，只要缺一层颜色就散。
- 泛光强度：内层 0.75（fresnel power 2.2）、外层 0.3（3.2），两条 arc 同步呼吸。

**还没做**：设计文档要求的「端面切角」冗余（颜色之外的第二编码）、drag 的上色版本、色觉模拟下的一次验证。

## 11. 这一轮（配色压深 / drag 辉光 / hold 改成平片）

| 项 | 之前 | 现在 |
| --- | --- | --- |
| 青釉 / 赤釉 | `#0f6c7d` / `#8f1124`（还是有点糖果感） | `#0a4e5a` / `#6a0f18`（深青 / 酒红，压暗一档） |
| 中性 hit | `#7d838b`（偏亮） | `#5a6067`（更灰） |
| drag | 0.15 × 0.016 × 0.03，无辉光 | 0.195 × 0.011 × 0.022，水平加法辉光片（0.3 × 0.12） |
| hold | 玻璃管 ⌀0.048 × 0.8，内部灌注 | 贴轨平片 0.21 × 0.006 × 1.2，片内亮带 55% |
| arc 管壁 | opacity 0.42（太透） | 0.58（中性玻璃也 0.32 → 0.45） |

- drag 的辉光**没有用壳层**：薄片键的菲涅耳壳层会在近端 / 远端两个面上爆亮，读起来像两个端点在发光。改成一张水平铺开的加法渐变片（`createGlowTexture`），从上方俯视时是一圈柔光，不会破坏「细条」的轮廓。
- hold 的亮带**不是盖一层白板**：之前用整宽的发光片，结果读成一块白色面板。现在是 0.07 宽的窄带，才是「片子里被点亮的那一段」。
- 设计文档已同步：hold 从「光滑玻璃管 + 管内液体」改为「光滑玻璃片 + 片内推进的亮带」，§2 / 4.1 / 4.2 / 4.3 与修订记录都改了。

**待你判断**：hold 平片的**长边**（沿轨道方向）现在是 1.2m；如果你说的是「长宽都 ≈ 轨宽」（0.23）的小方片，改 `holdLength` 一个常数即可。

## 12. 第三次配色收敛 + hold / arc 辉光

| 项 | 之前 | 现在 |
| --- | --- | --- |
| 青釉 | `#1f4d55` | `#1b363c` |
| 赤釉 | `#53262d` | `#431e24` |
| 青玻璃 / 赤玻璃 | `#2c7482` / `#7a2530` | `#2e6b76` / `#743038` |
| hold | 无辉光 | 片底一张加法渐变片（0.42 × 1.5） |
| arc | 两层菲涅耳壳 | 壳 + 台面光斑（0.3 × 1.7，带手别色） |

**配色**：两轮都往「压暗」走，这一轮改成**降饱和**。实测全身平均色：

| | 渲染色 | 饱和度 | 明度 |
| --- | --- | --- | --- |
| 青釉 | `#487b8f` | 49% | 56% |
| 赤釉 | `#783e52` | 48% | 47% |
| 无釉 | `#a0aebf` | 16% | 74% |

从「霓虹」退到「深色釉」：颜色还在，但不抢眼睛。中性仍是亮度最高的一条——这是刻意的：无釉瓷本来就比带釉的亮，玩家读「这条不锁手」靠的就是这点亮度差。

**辉光**：hold / arc / drag 现在用同一套加法渐变片（`createGlowTexture`），差别只在摆法：

- drag：贴在冰条下方，0.3 × 0.12；
- hold：压在平片底下，玻璃半透，光从片里透出来；
- arc：铺在轨道上，跟着弧的色相（青 / 赤），读作「光从弧上洒下来」。

arc 的两层菲涅耳壳保留，但半径收到 0.032 / 0.062、功率提到 2.0 / 2.6——只负责勾一圈边。试过把外圈放大到 0.09、功率 1.15，结果不是辉光，是一层「玻璃斗篷」。

## 15. 修 bug + hold 的真实规则

### 修的 bug

### hold 改成真规则

| 规则 | 实现 |
| --- | --- |
| 必须按手柄按键 | 扳机（select / 食指）或侧握（squeeze / 中指），任意一个按着才算「按住」。桌面用鼠标左键或空格 |

| 不会严过 200ms | 上面的下限就是 0.2s——密度再高也不会更窄 |
| 判定 | 所有物量都被按住 → PERFECT；否则 MISS（物量级的按比例计分留给计分系统） |

## 16. hold 按住的特效 + 相机修正

### 按住的特效

之前只有「HOLDING」这几个字，片子本身没有反应。现在按住时同时有四层反馈：

| 层 | 做法 |
| --- | --- |
| 片子本体 | 每条 hold 用自己的材质副本，按住时 `emissiveIntensity` 0 → 2.0（带 14 rad/s 的脉动），opacity 0.45 → 0.70 |
| 片子底下 | 一张加法辉光片（复用 `glowLeft` 的渐变贴图），随片子裁剪后的长度拉伸，opacity 0 → 0.55 |
| 手下 | 一个加法 Sprite 光斑，跟着手、脉动缩放，按得越稳越亮 |
| 亮带 | 已经越过判定带的那一段，opacity 0.5 → 0.9 |

四处都做 `glow` 的 0→1 过渡（12/s），所以按下的瞬间是「亮起来」而不是硬切。

### 相机修正

上一版为了腾出鼠标，直接把 `controls.enabled` 关了——结果 `?cam / ?look` 也不生效了（`controls.update()` 才负责把相机对准 target）。现在改成：

- `controls.enabled` 保持（XR 中除外），
- 打击练习开着时只关 `enableRotate` / `enablePan`。

鼠标仍然是手、左键仍然是按键，但相机也能正常对准。

## 19. 判定从「距离」改成「时间」

你指出的问题成立：之前 drag / hit 的窗口是**米**，流速一变，同一个窗口对应的毫秒数就变了（3 m/s 下 ±0.5m = ±167ms，0.5 倍速下就变成 ±333ms）。现在全部改成毫秒。

### 规则

| 键型 | 判定窗口（毫秒） | 分级 |
| --- | --- | --- |
| hit | ±80ms = PERFECT，±160ms = GOOD | 完美 / 好 / 漏 |
| drag | ±120ms | 完美 / 漏 |
| hold 的物量 | `clamp(时长/物量数, 200ms, 600ms)`，最窄 200ms | 完美 / 漏 |

- **挥击速度 / 挥击距离**（hit）现在只作为**门槛**：速度 ≥1.4 m/s、120ms 内移动 ≥0.15m 才算「打到了」；打到了之后，perfect / good 只看时间。
- 手不再需要「碰到那颗键的 z」：要求手落在**判定带 ±0.4m** 的范围内。这样判定点固定在判定线上，不会因为键还在远处就提前算命中。
- 漏：超过正向窗口就记漏（hit 160ms、drag 120ms），键继续滑出去。

### 验证

同一份测试串，`?flow=1` 和 `?flow=6` 两次跑，第一次命中的结果都是 `PERFECT -28ms`：

![flow=1](.scratch/x3-slow-diag.png)
![flow=6](.scratch/x4-fast-diag.png)

（两行截图分别来自 1 m/s 和 6 m/s 的流速，判定读数完全一致。）

### 关于谱面变速段

判定现在只依赖每颗键的 `arriveAt`，视觉位置 = `bandZ - 流速 × (arriveAt - now)`。所以：

- 玩家调流速 → 只改视觉；
- 谱面写变速段（0.5× / 2×）→ 只改视觉，判定窗口不动。

真正的变速段还没做（现在只有全局流速），但架构上已经不需要为它改判定——只要把「当前位置」换成对速度曲线的积分即可。

## 20. arc：跟着滚过来的弧

### 模型（按 Arcaea 的算法改的）

第一版把弧做成了「固定在世界里、光点沿弧走」——你说得对，那版弧完全不动。现在改成：

- 弧是一组「时间 → (x, y)」的控制点，**判定位置随时间沿弧移动**（`u = 时间进度`）；
- 弧同时按时间轴展开成一条 3D 管：局部 `z = -流速 × (t - 起点)`，
  整条管再按 `bandZ + 流速 × (now - 起点)` 平移——于是它像别的键一样朝玩家滚过来；
- 判定点（光点）永远落在判定带上：手要跟着它在 (x, y) 上移动，z 只要在判定带 ±0.35m 内。

这就是 Arcaea 的做法：弧是时间曲线，玩家在判定线上跟它的 x；区别只是我们把 y（高度）也做进了曲线，所以弧可以在空中起伏。

### 物量

| 类型 | 分布 | 判定半径 | 窗口 |
| --- | --- | --- | --- |
| 普通物量 | 沿弧均匀（6 个） | 0.19m | 200ms |
| **关键物量** | 谱面指定（现在 u=0.34 / 0.72） | **0.19m（与普通相同）** | **80ms** |

- 判定带 z 方向的手部容差从 ±0.35m 放宽到 ±0.42m；普通物量的判定半径从 0.14m 放宽到 0.19m。
- **关键物量的判定半径与普通物量相同（0.19m）**：它只靠更短的窗口（80ms vs 200ms）区分，难度不来自缩小体积。
- 关键物量在弧上有**黄铜珠**标记。
- 逐物量结算：接住当场弹 PERFECT，漏了当场弹 MISS。
- 普通物量可以重连（窗口内贴回来就行）；关键物量只认那 120ms。

### 视觉

- 青 / 赤玻璃管 + 管芯 + 两层菲涅耳泛光（`materials/glow.ts`，和键型预览共用）。
- 光点：小球 + 加法光晕。
- 手跟上时整条弧发光（玻璃自发光 + 泛光强度）。
- **近端裁剪**：弧滚过判定带 0.1m 就被裁剪面切掉，不会穿过玩家（第一版直接滚到脸上）。
- 弧在渲染上靠一个世界空间裁剪面（`renderer.localClippingEnabled`）。

### 踩到的坑

- 弧一开始不显示：不是裁剪的问题，是**回收循环**把它当成「滚过近端的键」删了——弧的 group.z 本来就一直在增大。现在回收循环跳过 arc，由它自己的结束条件回收。

### 测试串

一波四种：**hit 串 → arc → drag 楼梯 → hold**。arc 每次换手（第一次右手 / 赤）。
`?auto=1` 的虚拟手会直接贴着光点走。

### 参考

- Arcaea 的机制里，弧是随时间变化的曲线，玩家在判定线上跟随；关键点/物量的判定与普通段不同。参考：[Arcaea 机制（wiki）](https://wiki.arcaea.cn/index.php?title=%E6%9C%BA%E5%88%B6)、[Arcaea Scoring](https://arcaea.fandom.com/wiki/Scoring)。
- 关键物量是我们自己的设计（Arcaea 没有这个分类），所以 120ms / 0.09m 是拍脑袋定的，等你打过再调。

### 27.2 音频时钟（`src/audio/`）

之前是「假时钟」：每帧把 `dt` 累加到 `clockMs`。帧率一抖，键就晚到；而且没有声音。

现在：

- **主时钟 = `AudioContext.currentTime`**，`now()` 返回**正在被听到的**谱面时间（加了 `outputLatency` / `baseLatency`）。判定的 0ms = 耳朵里的拍点。
- 音频排程用同一个 `now()` 反算：`ctx.currentTime + (t − now()) / 1000`，提前 300ms 排进音频图，主线程抖动不会变成漏拍。
- **双锚点**：同一个瞬间同时记下「音频时间」和「performance 时间」。音频被系统挂起、或从 performance 切到音频时钟时重打锚点，谱面时间不跳。
- 浏览器不给自动播放时退回 `performance.now()`：游戏照常跑，只是没声音；第一次手势（点 Enter VR）后自动接上音频时钟。
- **lead-in 2s**：从 −2000ms 起播，`timeline` 支持负数时间（远端外推第一档速度），键从远处滑进来。
- `meta.offset` 直接落到「校准偏移」，正值 = 谱面提前。
- **合成音轨**：没有音频资产，所以按 `timing` 现场合成鼓组 + 贝斯 + 可选节拍器（`src/audio/track.ts`）。它和谱面共用同一张 timing，天然对齐。
- 有真实音轨时（`?audio=/track.mp3`，文件放 `prototype/public/`）鼓组退化成可选节拍器。
- 暂停 / 恢复：`ctx.suspend()` / `resume()`，恢复时跳过已经排进音频图的那一小段，避免重复击打。

示例谱面同时做了**量化**：BPM 150（一拍 400ms），所有 note 都落在拍点上（原来是手写的零散时间，和它自己的 BPM 对不上，音轨一响就会听出来）。

## 28. 视距淡出返工：逐片元 + arc / hold / drag

上一版的淡出是「每颗 note 一个整体不透明度」。你指出的三个问题都出在这里：

- **arc 从老远就出现**：管子的几何一直伸到台面之外，整体透明度压不住它；而且头部的光点没有参与淡出，会在很远处留一颗红点。
- **hold 突然出现**：整条片子共用一个 alpha，尾端刚进台面时整条一起亮；而且玻璃太透，远处几乎看不见，到跟前才「显形」。
- **drag 只剩辉光**：条子和辉光共用同一个 alpha —— 加法混合的辉光在低 alpha 下仍然显眼，冰条却先没了。

### 28.1 改成逐片元（`src/materials/distanceFade.ts`）

- 世界 z 直接进 shader：`gl_FragColor.a *= pow(clamp((worldZ − farZ) / span), power)`。
- 参数烘进源码（不用 uniform），同参数材质共用一个 program；`customProgramCacheKey` 把参数编进 key。
- 于是：**长物体从远端「长出来」**，而不是整条一起闪。
- 每颗 note 的材质克隆也取消了（hit / drag 回到共享材质），只有 hold 仍按颗克隆（它要单独改自发光）。

### 28.2 三条各自的处理

| 对象 | 处理 |
| --- | --- |
| arc | 管壁 / 芯 / 两层菲涅耳辉光 / 黄铜珠都加逐片元淡出；**头部的光点按世界 z 单独淡出**（它就是「老远一颗红点」的来源） |
| hold | 逐片元淡出（整片从远端渐显）；远端判据改成「近端还在台面上就画」；玻璃**保留 0.22 的底自发光**、底色不透明度 0.45 → 0.52，远处能读成一条片子；另外在片子近端加了一条**亮边（冰条）**，标出该按下的位置 |
| drag | 冰条的自发光 2.2 → 3.4；辉光的淡出指数 1 → 2.4（加法辉光淡得比条子快，远处不会再「只剩一团光」） |

### 28.3 渲染验收

- `?warp=0.5`（arc 还差 4.7s）：远端只剩空气，没有红点。
- `?warp=1.15 / 1.3 / 1.6`（hold 逐年逼近）：片子从台面远端渐显，亮边在前。
- `?warp=2.4 / 3.2`（hold 近身）：亮边 + 磨砂片子，按下时光带从判定带往远端铺。

## 31. 真正的元凶：台面把 note 盖掉了

前几轮我一直在调淡出曲线，其实问题不在淡出。用 `?warp=1.6&freeze=1` 把 hold 的片子改成纯红之后，
画面里**一个红像素都没有** —— 网格根本就没画出来。

### 31.1 渲染顺序

- 台面的 6 条轨面是 **transparent**（shift 时要交叉淡入淡出），而且它们的 mesh 位置在**原点**
  （几何是用 `geometry.translate` 挪过去的）。three 对透明物体按「到相机的距离」排序时，
  用的是 mesh 的 `matrixWorld` 位置 —— 于是整块 10m 长的台面被当成「离相机最近」，排在所有 note **之后**画。
- hit 用的是釉面（`depthWrite: true`），先写深度，台面后画时深度测试失败，所以 hit 一直正常。
- **drag 的冰条 / hold 的玻璃片都是 `depthWrite: false`**，于是被台面整个盖住；
  而辉光片有 `renderOrder = 4`，排在台面之后 —— 所以只看得到辉光。
- 修法：note 的实体统一 `renderOrder = 5`，glow 6，aura 7（arc 同样）。台面 / 分割线 / 判定带都在 3 以下。

### 31.2 视距裁剪把缩放过的 mesh 剔掉了

hold 片子和 drag 条子每帧都在改 `scale`（长度 / 补厚度）。这类 mesh 会被 `frustumCulled` 误判剔除，

（数量只有几十个，省这点裁剪没有意义）。

### 31.3 顺带修掉的

- note 不再投影：影子不跟着淡出，远处就是一条黑杠（「远处不是透明，是黑的」）。
- 视距回到 **9m**（贴着台面远端），淡入 **4m**；实体的淡出指数 0.6–0.8（先保持实心，靠边才掉），

### 35.2 踩到的坑 / 决定

- **高度 y=0 的把手贴边抓不到**：高度轨 / SV 轨的 y 映射上下各留 8px；不然点 `y=0`
  会落进相邻的带里。这是测试时发现的，不是设计。
- **arc 首点**：`points[0].time` 必须为 0，所以拖首点改的是 `note.time`（整条弧的起点）；
  末点时间 = 弧长。
- **offset 与波形**：谱面时间 `t` 对应音频 `t − offset`（正 offset = 谱面提前），
  所以波形按 `t − offset` 取样绘制。
- **音频时钟不能倒退 / 0.5×**：`AudioClock` 只服务 1× 正放；其他模式手动时钟 + 静音。
- **预览重建**：拖动中不重建播放器，松手后再建；否则每 180ms 拆一次。
- **排序**：每次改动都 `sortChart`，选中靠对象引用，所以排序不会丢选区。
- **无效 note**：编辑器不阻止越界，只画红点 + 校验报错；播放器仍会生成它（和游戏一致）。
  这样能看见错误，而不是「放不进去但不知道为什么」。

## 38. 制谱器第四轮修正（2026-10-18）

这轮针对 arc 编辑、3D 手感、时间吸附和风扇噪音。

### 38.1 3D arc 编辑层

之前 3D 里拖 arc 只有整条平移，而且播放器里的弧几何是创建时烘死的：
拖动只改了数据，画面要等松手后 180ms 重建才动，所以看起来「完全不跟手」。
这轮新增 `src/editor/arcEdit.ts`，在 3D 里直接画一层独立的 arc 编辑层：

- 选中弧后，播放器里那条旧几何临时隐藏，编辑层按**同一套滚动公式**实时重建；
- 白球 = 控制点，自由拖 x/z；
- 青球 = **只改 x**；黄铜球 = **只改 z**（和高度/平面分开调）；
- ARC 工具点弧身 = 在 SNAP 吸附后的时间插点，并直接拖这个新点；
- 弧上所有物量珠都画出来：普通青色、KEY 黄铜；**点一下直接切 KEY**，
  AUTO 物量会先转成显式 `ticks[]`；
- 控制点和 KEY 完全重合时，点击优先选控制点；用检查器的
  `MAKE / REMOVE KEY @ POINT` 处理这个时刻的 KEY；
- 3D 里的弧点只改 x/z；点的时间仍在 2D / 检查器改。

拾取优先级是 **控制点 / 轴把手 / 物量珠 > 弧身**：急弯处弧身可能比控制点更靠近相机，
但白色把手是 `depthTest:false` 画在最上面的，点击语义必须跟视觉一致。

### 38.2 时间吸附：预设 + 自定义

不再堆一长串下拉项：

  完全没有时间对齐；

### 38.3 性能：暂停时不再空转

风扇吵的原因不是 UI，是主循环每帧都在做重活：

- `preview.update()` 每帧无条件 `renderer.render(scene, camera)`（整个 3D 场景）；
- 控制器每帧 `renderer.render()`（2D canvas 整层 blit）和 `overview.render()`

- 即使暂停、没有拖动，也一直按 60Hz 跑。

现在：

- 3D 只在**播放 / 拖动 / 悬停 / 相机阻尼 / 选中变化 / 谱面变化**时重绘；
- 2D 和底部总览只在 `uiDirty` 或播放时间变化时重绘；
- 暂停且没有操作时，`preview.update` 直接返回，`player.update` 也不跑；
- 3D 像素比从 2× 降到 1.5×（编辑器不是游戏画面）。

（约 9.6% → 1.5% CPU），脚本时间 0.041s → 0.015s，布局 / 样式重算 0.10s → 0。

## 44. 音频频谱 / 自动完美（2026-10-18）

### 44.1 可展开音频频谱

## 52. 音频 offset 起播 / snap 线（0.3.10）

### offset 起播

之前 `AudioClock.play(fromMs)` 把 `fromMs` 直接作为 raw 锚点，而 `now() = raw + offset`，
所以 `offset = -750` 时点 0 秒会从 -750ms 开始，`+750` 时从 +750ms 开始。

修正后的语义：

- `play(fromMs)` 的 `fromMs` 永远是**谱面时间**；起播瞬间 `now() === fromMs`；
- raw 锚点 = `fromMs - offset`；
- 音轨内容从 raw 位置开始，offset 只负责音频 / 谱面的相对平移；
- 当 raw 为负时先静音，等谱面时间走到 0 再出声；
- seek / 重播 / 从暂停恢复都走同一套逻辑。

实测 offset 从 -750 / +750 起播，播放头都在 0 附近（约 200ms 后 219 / 235ms），
不再跳到 ±offset。

### snap 线

2D 主视图的 grid 对比度小幅提高：

- 小节线 `0.24`
- 拍线 `0.11`
- 细分 / snap 线 `0.075`
- 选中 note 的 snap 引导线 `0.30`
