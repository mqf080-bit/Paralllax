## 0. 一句话

现在的游玩端是**“进 VR 就直接打”的 demo 流程**：没有入口、没有选歌、没有准备页，UI 是一块常驻的仪器面板。
下一步要从“demo”变成“产品流程”：

```text
进入 VR → 欢迎 / 主页 → 选歌 → 准备 / 校准 → 游玩
                                      ↓
                                   暂停（二级设置）
```

同时，游玩中的**激光误触路径必须关掉**：按住 hold 时，激光不能点到暂停 / 设置。

---

## 1. 约束与边界

- **设备基准**：Meta Quest 3，WebXR，控制器优先；不依赖手追踪。
- **桌面 fallback 必须保留**：鼠标 = 手，左键 / 空格 = 扳机。
- **不改判定 / 谱面 / 渲染**：这一轮只动 UI 流程、层级与输入路由。
- **性能**：72fps 底线；UI 不能引入每帧重绘或额外 draw call 尖峰。
- **视觉方向**：用户给定「**现代简约 + 复杂**」——不是“辅助（assistive）”，不是把内容删空的极简；要保留信息量，用结构、层级和更现代的排版把它组织清楚。P1 具体方向待选。
- **不破坏现有入口**：`?chart=`、`?pack=`、`?localPack=1` 仍要能用，方便调试。

## 3. 详细记录

### UI-01 — 进入 VR 没有入口，谱面立即播放

**现状**

- `sessionstart` 时直接调用 `restartPlayback()`，从 lead-in 开始播放；
- 页面启动时也会自动 `restartPlayback()`；
- 没有“欢迎 / 主页 / 继续 / 退出”的中间状态。

**影响**

- 玩家不知道自己在打什么，也没有机会选歌、调设置、校准；
- 第一次进入像测试 demo，不像一个可消费的 VR 游戏；
- 无法从游玩中回到主页，也无法安全地换歌。

**期望**

- 进入 VR 后先到**欢迎 / 主页**，不自动播放音频与谱面；
- 主页至少提供：`START`（默认 / 上次曲目）、`SONGS`、`SETTINGS`、`QUIT`；
- 玩家明确开始后才进入 lead-in；
- 从暂停可以 `QUIT TO HOME`，结果页也可以回主页；
- 会话中断 / 重进时，行为明确：回主页，或恢复上次状态（二选一，不能默默重开）。

**验收**

- 进入 VR 后 5 秒内没有谱面开始、没有音频；
- 从主页到开始游玩不超过 2 次点击；
- 暂停 → 回主页 → 再进曲目，状态正确；
- 桌面 fallback 仍可通过 URL 直接进谱面调试。

**未决**

- 主页是 3D 舞台空间，还是贴在玩家前方的面板？
- 默认曲目用哪张谱？`TEST_CHART`、上次选曲，还是 `Infinity Heaven`？
- 主页是否显示最近游玩 / 成绩？

### UI-02 — 没有选歌 / 曲目信息

**现状**

- 曲目通过 URL 参数或默认 `TEST_CHART` 决定；
- 游戏内没有曲目列表，也没有封面 / 作者 / 难度 / 时长的选择界面；
- `.parallax` 本地包只能从页面左下角的桌面控件加载。

**影响**

- 玩家不能“选一首想玩的”；
- 制谱者做完新谱后，仍然要改 URL 才能进游戏；
- 未来做曲库时，入口会再次返工。

**期望**

- 曲目列表：封面、标题、作者、难度、时长、物量；
- 支持键盘 / 控制器导航，支持“上次选择”；
- 曲目来源先支持：内置谱面 + 浏览器 IndexedDB 里的本地 `.parallax`；
- 选中后进入准备页，而不是直接开始。

**验收**

- 至少 3 张谱可在 VR 内切换；
- 不修改 URL 也能完成“选歌 → 开始”；
- 本地包出现在列表里，刷新后仍能看到（IndexedDB）。

**依赖**

- 曲库 / workspace 方案见 [FUTURE.md](FUTURE.md)；
- 这一轮可以先做“内置列表 + 本地包”，不提前做完整 library。

### UI-03 — 没有游玩前设置与校准

**现状**

- 设置只在游玩中打开：`CHART SPEED`、`AUDIO OFFSET`、`VOLUME`；
- 没有游玩前的音量 / 延迟试听、没有台面高度校准、没有左右手 / 站姿选择；
- 高度基准是固定的 0.95m 台面。

**影响**

- 第一次玩的人不知道 offset 该调多少；
- 不同身高 / 站姿的玩家，台面和判定带可能不合手；
- 设置藏在游玩中，玩家只能“先开一局再调”。

**期望**

- 准备页提供：音量、音频 offset（可试听节拍）、流速、台面高度、左右手、站姿 / 舒适选项；
- 提供“试打一下”区域：一个 hit / hold / arc 的短测试，不进入正式谱面；
- 设置改动即时生效并可保存；
- 开始前可以返回选歌。

**验收**

- 不进入正式谱面也能完成一次 offset / 音量 / 高度调整；
- 设置持久化，重新进入后保留；
- 准备页返回选歌不丢当前选择。

### UI-04 — VR UI 不清爽、偏老气

**现状**

- 面板是“仪器语言”：暗玻璃渐变、黄铜细线、四角刻度、全大写 + 字距、等宽数字；
- 控制条常驻右前方，播放时淡到 30% 仍然可见；
- 三个按钮等权排列：`SETTINGS / PAUSE / RETRY`；
- 设置页是密集的“标签 — 数值 — ± 按钮”列表；
- 视觉反馈主要是静态 canvas 重绘，没有明确的层级动画。

**影响**

- 读起来像调试面板 / 工业仪表，而不是消费级 VR 游戏；
- 常驻控制条占据视野，和“仪器感”叠加后显得杂乱；
- 主操作（继续游玩）和危险操作（重试）没有明显层级；
- 头显里字体、对比度和面板距离还需要实测。

**期望**

- 保留“精密仪器”的材质语言，但**减少常驻元素**，把信息分层；
- 游玩中只保留必要的状态（分数 / 连击 / 血条），控制入口收进暂停层；
- 面板排版更干净：更少的全大写、更明确的字号层级、更多留白；
- 按钮有明确主次，危险操作（重试 / 退出）不与主操作并排；
- 动画只服务于层级变化，不做装饰性演出。

**验收（开工后）**

- 先有桌面 + Quest 3 的基线截图，再谈“好看”；
- 1.5m 距离、头显内可读；不靠小字；
- 常驻 UI 元素数量减少，游玩视野不被控制条占据；
- 72fps 不掉；
- 视觉方向经过一次明确选择，不直接“改成默认科幻风”。

**未决**

- 保留仪器感，还是转向更轻的“驾驶舱 / 极简 HUD”？
- 游玩中是否完全不显示按钮，只保留手腕 / 掌心菜单？
- 主页和暂停页是否共用一套面板组件？

### UI-05 — 按住 hold 时激光可能点到暂停 / 设置

**现状**

- 控制条固定在右前方 `(0.64, 1.10, −0.60)`，游玩中仍然可见、可交互；
- 两只控制器都有激光射线，面板命中即可点击；
- `hands.ts` 只把 `selectstart / selectend / squeezestart / squeezeend` 合成一个 `pressed`；
- hold 需要按住扳机 / 侧握，而这个 `pressed` 同时被 UI 用来判断点击；
- 没有“游玩中输入只给判定，不给 UI”的模式隔离。

**影响**

- 打 hold 时手在右前方移动，激光扫到控制条就可能触发 `PAUSE` / `SETTINGS` / `RETRY`；
- 这是**直接破坏游玩**的问题，优先级高于视觉；
- 即使把控制条淡到 30%，点击判定仍然存在。

**期望**

- 游玩中**没有可直接点击的暂停 / 设置按钮**；
- 暂停只能通过明确的手柄按钮（左手 menu）或明确的系统级手势触发；
- 设置只能从暂停层进入；
- 激光在游玩中不参与 UI 点击；或者 UI 层只在暂停时接收射线；
- hold 的 `pressed` 与 UI 的点击边沿彻底分离。

**验收**

- 在控制条原位置附近连续做 hold 30 秒，不触发任何 UI；
- 左手 menu 能稳定打开暂停；
- 暂停后激光可以正常点按钮；
- 恢复游玩后 UI 点击立即失效；
- 桌面 fallback 仍能暂停（Esc / 指定键）。

**实现提示（未开工，仅供后续）**

- 把“手”与“UI 指针”拆成两条输入路径；
- UI 只在 `paused / home / settings` 状态接收 `select`；
- 游玩中控制条隐藏或 `raycast` 禁用；
- 不要用同一个 `pressed` 同时服务 hold 和按钮。

### UI-06 — 暂停 / 设置 / 重试没有清晰层级

**现状**

- `PAUSE` 只是暂停音频，控制条仍在；
- `SETTINGS` 可以直接从游玩中打开；
- `RETRY` 和 `SETTINGS` 并排；
- 暂停没有“恢复 / 重开 / 设置 / 退出”的统一面板；
- 结果页与暂停页是两套独立面板。

**影响**

- 玩家不清楚“现在在哪一层”；
- 设置与暂停的关系不明确；
- 误触 `RETRY` 的成本很高；
- 未来加选歌 / 主页时，层级会继续打结。

**期望（建议的信息架构）**

```text
游玩
  └─ 暂停（左手 menu）
       ├─ 继续
       ├─ 重新开始
       ├─ 设置（二级）
       └─ 退出到主页
```

- **设置是暂停的二级页**，不是游玩中的直接入口；
- 游玩中按左手 menu：打开暂停层（如果需要“直接到设置”，可以记住上次的 tab，但不跳过暂停状态）；
- 结果页提供：重试 / 返回主页；
- 危险操作与主操作分开，重试需要明确选择。

**验收**

- 任意时刻按 menu，都进入同一个暂停层；
- 设置返回后回到暂停，不直接回游玩；
- 暂停期间谱面时间 / 音频冻结，恢复后不跳；
- 退出到主页后，再次开始是干净状态。

**未决**

- 左手 menu 是“打开暂停”还是“直接打开设置”？建议前者；设置作为暂停里的 tab / 二级页。
- 暂停层是 3D 世界面板，还是跟随视线的 overlay？需要和视觉方向一起定。

### UI-07 — 左手 menu 按钮在 WebXR 中是否可用未验证

**现状**

- `hands.ts` 只监听 `selectstart / selectend` 与 `squeezestart / squeezeend`；
- `gamepad` 对象目前只用于触觉，不读取按钮；
- 没有 menu 按钮的输入路径。

**待验证的假设**

> “不同 VR 控制器应该都有一个非系统独占的 menu 按钮吧？”

这个假设**不能直接当成事实**：

- Quest 3 左手柄确实有 menu 按钮，但 WebXR / 浏览器是否把它暴露给页面，取决于 runtime 与 `xr-standard` 映射；
- 系统保留按钮可能被 OS 拦截，不会出现在 `XRInputSource.gamepad.buttons`；
- 不同厂商（Quest / SteamVR / Pico / Index）按钮布局与保留策略不同；
- 即使能读到，也不一定所有控制器都有同一个“menu”。

**下一步验证（开工时）**

1. 在 Quest 3 的 WebXR 会话里打印 `inputSource.gamepad.buttons` 的 `pressed / touched / value`；
2. 逐个按左手柄按钮，记录索引与名称（如果 runtime 提供 mapping）；
3. 确认 menu 是否被系统占用；
4. 如果不可用，设计 fallback。

**Fallback 候选**

- 左手 `Y` 长按（避免单击误触）；
- `squeeze + trigger` 组合键；
- 手腕 / 掌心菜单（看向手腕打开）；
- 暂停按钮放在玩家身后 / 侧面，必须明确转身才点到（不推荐，累）；
- 桌面 / 调试用 `Esc`。

**验收**

- Quest 3 上至少一条可靠路径能打开暂停；
- 不与其他系统手势冲突；
- fallback 在 UI 上有提示，不需要玩家猜。

## 7. P0 实现记录（2026-10-20）

### 已做

- **入口**：`sessionstart` 不再自动播放；正常进 VR 落在主页，显示当前谱面的 `CHART / ARTIST / DIFFICULTY / LENGTH`，按 `START` 才开始；主页可直接进 `SETTINGS`，VR 内多一个 `EXIT VR`。
- **游玩中无 UI**：移除了右前方的常驻 `SETTINGS / PAUSE / RETRY` 控制条；`GameUi` 在 `playing` 模式直接返回，不接收任何面板点击。hold 的扳机 / 侧握仍然只服务判定。
- **暂停层级**：`Pause` 提供 `RESUME / RESTART / SETTINGS / HOME`；`SETTINGS` 是暂停的二级页，`BACK` 回到暂停；结算提供 `RETRY / HOME`。
- **菜单输入**：
  - 优先读 `XRInputSource.gamepad.buttons[6]`（可用 `?menuButton=N` 改索引）；
  - 读不到时，**左手 Y 长按 400ms** 兜底；
  - 连接时打印 `[hands] left · mapping … · N buttons`，方便在 Quest 上确认。
- **桌面 fallback**：`Esc` 在游玩 / 暂停 / 设置之间切换。
- **调试入口**：`?autostart=1` 直接进游玩；`?panel=home|paused|settings|result` 直接摊开面板；`?vr=1` 假装在 VR 里检查 `EXIT VR`；`?clock=0` 仍可关音频。

### 已验证

- `npm run typecheck` 通过。
- CDP 流程：主页 → 点击 `START` → 游玩 → `Esc` → 暂停 → `SETTINGS` → `BACK` → 暂停 → `RESUME` → 游玩 → 暂停 → `HOME`，状态全部正确。
- 截图：早期 P0 截图已清理；当前布局见 `docs/ui-p2`。无控制台错误（只有 three 的 PCFSoftShadowMap 弃用警告）。
- 游玩中四个面板全部隐藏，`GameUi.update` 不处理点击。

### 还没验证

- **Quest 3 上 `buttons[6]` 是否真的是 menu 键**。规范允许 UA 保留系统键；如果读不到，Y 长按就是实际路径。
- 头显内面板距离、字号、可读性（P1 视觉评审）。
- 真实 hold 过程中手扫过原控制条位置时不再误触——需要头显实测确认。

## 8. P1 补充（2026-10-20）

### UI-08 — VR panel 离人太远

**现状**

- 主页在 `(0, 1.38, −0.95)`，暂停 / 设置 / 结算在 `(0, 1.34, −0.90)`；
- 桌面相机在 `z = +0.52`，实际距离约 **1.4m**；头显里玩家站位更靠后时还会更远；
- 面板宽度 0.86–0.96m，为了“看得清”已经做得很大，但视觉上仍然像隔着一层玻璃看仪表。

**期望**

- 主页距离约 **0.75–0.85m**，暂停 / 设置约 **0.70–0.78m**；
- 同时按距离缩小物理尺寸，保持水平视角约 **50–58°**，不要因为拉近而占满视野；
- 面板中心略低于视线，避免长时间仰头；保持世界固定，不做跟随头部的 overlay。

**验收**

- 站立时不用前倾就能读清标题、标签、数值；
- 伸手 / 激光不用“够”就能点到按钮；
- 面板边缘不压到台面 note，也不挡判定带；
- 72fps；面板拉近不增加 draw call。

### UI-09 — panel 像 iOS 6：拟物、老气

**现状**

- 暗玻璃渐变 + 黄铜细线 + 四角刻度 + 全大写 + 大字距 + 等宽数字；
- 按钮是深色渐变 + 内高光 + 外发光，像早期拟物界面；
- 视觉重心在装饰边框，而不是信息本身。

**期望**

- **现代简约 + 复杂**：去掉拟物装饰，保留信息量；
- 一个主强调色（冷青 / 黄铜只作少量状态），其余用明度层级；
- 标题用 sentence case，减少全大写和字距；数值可以用等宽，但不要整屏 mono；
- 平面 / 轻透明表面、1px 边线、清楚的分组；不要重阴影、不要四角刻度、不要“玻璃斗篷”；
- “复杂”体现在信息结构：分组、层级、标签、状态、快捷提示，而不是再加装饰。

**验收**

- 远看能分出标题 / 主操作 / 次要信息三层；
- 近看没有无意义的装饰线；
- 同一屏内信息量比现在多，但不靠缩小字号；
- 与游戏内“精密仪器”的材质语言不冲突，但不再是 2012 年的拟物面板。

### UI-10 — 信息密度低

**现状**

- 主页 4 行，行距 58px；设置只有 3 行，右侧独立 ± 按钮占掉一整列；
- 大量空白，实际可用信息少；
- 暂停页只有 score / combo / time，缺少曲名、难度、当前流速等上下文。

**期望**

- 主页：曲名、作者、难度、时长、包来源 / 物量、最近游玩；
- 暂停：曲名、时间、分数、combo、流速、offset；
- 设置：把 speed / offset / volume 做成紧凑 stepper（`− 值 +` 一行），并增加 track / latency / build 等只读状态；
- 选歌：一行一首，封面缩略图 + 标题 / 作者 / 难度 / 时长 / 来源，支持键盘 / 控制器上下选择；
- 用 8px 网格和 2–3 档字号，不靠“把字缩小”提高密度。

### UI-11 — 选歌页缺少「如何加入曲谱包」的提示

**期望提示内容**

- 桌面：游戏页左下 `LOAD .parallax`，或把 `.parallax` 拖进页面；
- 文件夹：把包放到 `prototype/public/packages/`，用 `?pack=/packages/xxx.parallax`；

- 选歌页里给出一个短句 + 一个 `HOW TO ADD` 展开项，不要写成一大段说明；
- 如果当前没有本地包，空状态直接显示这条提示，而不是空列表。

**验收**

- 新用户能在选歌页 10 秒内知道怎么加一张谱；
- 提示不遮挡曲目列表；
- 桌面和 VR 看到的是同一套文案。

### 方向决定（2026-10-20）

- **先做 A（Technical Console）**；C（Editorial Grid）不作为另一套皮肤，等 A 在头显里成立后，只融合它的**排版网格 / 大数字 / 非对称层级**。
- A 的强调色必须与现有语义色分开：**青 = 左手、赤 = 右手、黄铜 = 判定**，所以 UI 强调色不再用青 / 赤 / 黄铜。
- 强调色候选：
  - **Signal Lime**（推荐）：`#C6F24E`，用于主按钮、焦点、进度、选中态；深石墨底上用近黑文字；
  - **Ice White**：`#EAF6FF`，最稳但个性弱，容易回到“冷色仪器”；
  - **Cobalt**：`#6B8CFF`，现代但偏通用科技感，和赤 / 青的区分度不如 lime。
- 强调色面积控制在 5–8%，其余靠明度层级；任何强调都不能只靠颜色，必须同时有标签 / 图标 / 位置冗余。

### 配色决定（2026-10-20）

- **最常见的强调色 = Glacier Blue `#9CC8FF`**：偏蓝、不偏青，和左手青 `#8FE6F2` 拉开；用于主按钮、焦点、选中、进度、active tab。
- **Lime 稀有**：`#C6F24E` 只用于 `NEW / CALIBRATED / PACK LOADED / success` 这类状态，单屏不超过 1–2 处，不用于主操作。
- **Ice White `#F2F8FF` 不做色块**：只做标题、主文字、大数字、顶部高光；它负责亮度，不负责色相强调。
- **黄铜 / 青 / 赤保持原语义**：黄铜 = 判定，青 = 左手，赤 = 右手；UI 不再用它们做强调色。
- 面积比例大致 **60% 石墨底 / 25% 文字与中性面 / 10% 浅蓝 / 3% lime / 2% 白色高光**。
- 任何状态都不能只靠颜色，必须同时有文字、图标或位置冗余。

## 13. 面板距离 / 尺寸调整（2026-10-20）

用户实测反馈：面板离得太近。第一次调到 0.56m 后仍然觉得近，第二次才把距离作为主约束。

### 最终值

- 尺寸：**1.55m 宽 × 0.959m 高**
- 位置：中心 `(0, 1.44, −1.35)`
- 到眼睛中心：约 **1.36m**
- 水平视角：约 **60°**（旧版约 103°）

旧值 `0.86m / 0.34m / 0.43m` 的问题是：面板物理上不算大，但贴着眼前，水平方向几乎占满视野，所以主观上就是「很近」。
第一次只做了同比放大（1.40m / 0.56m），视野占比没变，因此体感仍然近。

第二次不再坚持「保持原视野占比」，优先把距离拉到 1.35m；画面确实比原来小，但这是为了让眼睛有正常的聚焦距离。面板仍然比旧版宽 1.8×。

### 可调参数

- `?panelScale=1.05`：整块面板放大 5%
- `?panelDistance=1.5`：再拉远到 1.5m
- `?panelY=1.5`：整体抬高
- `?panelDistance=1.2&panelScale=1.1`：近一点、稍大一点

参数在 dev 和 Pages 生产站都生效；不带参数时使用默认值。

### 经验

- **VR 面板的「大」和「近」不是一回事。** 同比放大只改变物理尺寸，不改变角尺寸，不能解决贴脸感。
- 先调距离，再调尺寸；距离舒适后再决定面板多大。
- 可读性由角尺寸和纹理倍率共同决定，不能只看物理尺寸。

## 15. arc 流速 / 包 offset 修正（2026-10-20）

### arc 流速

- 游玩端 Settings 的 Speed 只改了 `playSettings.flowSpeed`，地面键每帧读 `baseSpeed()` 所以会变，
  但已经生成的 arc 没有收到 `setSpeed`，仍然按创建时速度走。
- 现在主循环检测 `playfield.settings.flowSpeed` 变化并调用 `playfield.setFlowSpeed()`；
  `Player.setFlowSpeed()` 会遍历 runtime 中的 arc 做 `group.scale.z *= new/old`。
- 已验证：3.0 → 5.0 后，4 条 arc 的 `scale.z` 从 1 变为 1.6667。
- editor 的 3D 预览本来就有这段同步，不需要改。

### 包 offset

- 之前游戏启动 / 切谱时把 `chart.meta.offset` 直接写进 `audioSettings.offsetMs`，
  Settings 的 Offset 就显示了包里的 `-750ms`，而且玩家校准会被包覆盖。
- 现在 `AudioSettings` 分成：
  - `offsetMs`：玩家校准，Settings 可见；
  - `chartOffsetMs`：谱面 / 包作者偏移，音频时钟内部相加，游戏 UI 不显示。
- 切谱只更新 `chartOffsetMs`，不会覆盖玩家 offset。
- 已验证：`?pack=infinity-heaven&panel=settings` 的 Offset 显示 `0ms`，包内 `-750ms` 仍在音频时钟里生效。
