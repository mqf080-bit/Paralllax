# Parallax 制谱器（Step 5）

> 入口：`http://127.0.0.1:5173/editor.html`（独立页面，不进 VR）。
> 谱面格式：[`CHART.md`](CHART.md) ｜ 进度与坑：[`STATUS.md`](STATUS.md) §35

制谱器只做一件事：**把同一份 `Chart` 数据画出来、改掉、再用 Step 4 的播放器验一遍**。
它不复制播放器，也不定义第二套格式 —— 导出文件就是游戏页读的那种 JSON。

---

## 1. 打开

```bash
cd prototype
npm run dev
```

- 游戏：<http://127.0.0.1:5173>
- 制谱器：<http://127.0.0.1:5173/editor.html>

第一次打开是空谱（150 BPM / 4 拍）。右侧 `CHART` 里有 **LOAD TEST / LOAD DEMO**，
可以直接载入内置的 41.6 秒验收谱或 12 秒示例再改。

编辑内容每 650ms 自动写进 `localStorage`（`parallax.editor.draft.v1`），刷新不丢；
音频文件不会进草稿（浏览器不能持久化本地文件），刷新后需要重新导入。
调试时可以加 `?fresh=1` 忽略草稿、从空谱开始。

## 2. 界面

```
┌ 顶栏：工具 / 吸附 / 缩放 / 校验 / 新建·导入·导出 / 草稿状态 ┐
├──────────────┬──────────────────────────────┬──────────────┤
│ 3D 预览      │ 时间轴                        │ 检查器        │
│ + 走带        │  标尺 / 波形 / 6 轨 / 高度 / SV │ 选区 / 事件   │
└──────────────┴──────────────────────────────┴──────────────┘
```

### 3D 预览

- 直接跑 `src/game/player.ts`：note 生成、SV 积分、shift、判定、自动打都是真的。
- 默认 **AUTO**：一颗光点替你把谱面打一遍（和游戏里的 `?auto=1` 同一套逻辑）。
- **FOLLOW**：播放头跑出视口右侧时自动滚动时间轴；关掉就完全手动。
- 预览里的相机可以拖动 / 滚轮缩放（OrbitControls），不影响谱面。

### 走带

| 控件 | 行为 |
| --- | --- |
| `▶ PLAY / ❙❙ PAUSE` | 播放 / 暂停。空格同效 |
| `⏮` | 回到 lead-in（−1s）并暂停 |
| `RATE` | 0.25× / 0.5× / 0.75× / 1× / 1.5× / 2× |
| `REV` | 倒放（R 键同效） |
| `AUTO` | 自动打 |
| `FOLLOW` | 自动滚动时间轴 |

**时钟**：1× 正放时用**音频时钟**（`AudioContext.currentTime`，含输出延迟补偿），
和游戏完全一致；慢放 / 快放 / 倒放时音频不可能跟着走，自动切成手动时钟并静音，
走带上的音频标签会显示 `FREE`（手动时钟）或 `LOCK`（音频时钟）。

## 3. 时间轴怎么读

| 带 | 横轴 | 纵轴 | 内容 |
| --- | --- | --- | --- |
| 标尺 | 时间 | — | 小节号、时间刻度、shift 标记（← 青 / ● 黄铜 / → 赤） |
| 波形 | 时间 | 振幅 | 导入音频的包络（已按 `meta.offset` 平移） |
| **主视图** | 时间 | **6 条轨（0–5）** | hit / drag / hold / arc 的轨位置 |
| **高度轨** | 时间 | **0–0.9m** | arc 的 y；三条基准线（胸 0.33 / 面 0.61 / 头顶 0.81） |
| **SV 轨** | 时间 | 倍率 | 变速曲线（1× 是黄铜虚线；负值在下面） |

- 主视图里**高亮的 4 条轨**就是当时的 shift 窗口（1–4 / 0–3 / 2–5），
  它随时间连续滑动；左侧轨号只在窗口内的 4 条上亮起。
- 不在窗口内的 note 会带一个**红点**，右侧 `VALIDATION` 同时报错。
- 选中对象时会出现白色竖线；arc 选中后，主视图和高度轨同时显示所有顶点。
- 导出的谱面可以直接放在 `prototype/public/charts/`，游戏页用
  `?chart=/charts/文件名.json` 打开（示例：`/charts/example.json`）。

## 4. 编辑操作

工具用 `1–5` 或顶栏按钮切换。

### 放置

| 工具 | 操作 | 结果 |
| --- | --- | --- |
| HIT | 左键点空处 | 在吸附点放一颗 hit |
| DRAG | 左键点空处 | 放一颗 drag |
| HOLD | 左键**拖** | 起点 = 按下点，终点 = 松手点（至少一格） |
| ARC | 左键**拖** | 两点弧：起点 → 终点，初始高度 0 |

放置时按住拖动可以继续调时间 / 轨号；松手前不会进预览。

### 选中 / 移动

`SELECT` 工具：

- 点 note → 选中；左右拖改 **时间**（吸附），上下拖改 **轨号**（整数）。
- hold：拖**尾部**改 duration；拖身体移动整条。
- arc：拖**身体**移动整条（时间 + 所有点的 x）；拖**顶点**改顶点的时间 / x。
- 高度轨：拖**顶点**只改 y（Shift 吸附到 0 / 胸 / 面 / 头顶）；拖**弧身**整条上下平移。
- SV 轨：拖点只改倍率（拖动范围 = 当前纵向显示范围，极端值用检查器输入）；
  时间 / 过渡时长 / 缓动在右侧检查器改。
- 标尺上的 shift 标记可以点选、左右拖动改时间。

### arc 的点列与缓动

- ARC 工具在**主视图点住已有弧身**：在该时间插入一个点并直接拖着走。
- ARC 工具在**高度轨点住已有弧**：在该时间、该高度插入一个点。
- 检查器列出全部顶点：`# / time / x / y / easing`。点一行选中它；
  非首点可以改「进入这段用的缓动」：

| 值 | 形状 |
| --- | --- |
| `linear` 直线 | 匀速直线段；连续两段直线 = 直角 / 钝角 |
| `sine` 缓入 | 慢起快收 |
| `cosine` 缓出 | 快起慢收 |
| `bezier` 缓入缓出 | 两端都慢 |

- 首点的 `time` 恒为 0；拖首点会移动整条弧的起点（`note.time`）。
- 末点的 `time` 就是弧长；`KEY OBJECTS` 是相对起点的毫秒数组（逗号分隔）。
- 缓动和 arc 形状用的是**和播放器同一份** `src/chart/easing.ts`。

### 删除

- **右键**光标下的 note / arc 顶点 / SV 点 / shift 标记：直接删。
- `Delete` / `Backspace`：删当前选区。选中 arc 端点时删整条弧；
  选中中间点时只删那个点。

### 插入点列

arc 的点列就是 `points[]`；可以任意多段，每段一个缓动。
想要「直角」就连续两段 `linear`；想要曲线就改后一段的缓动。

## 5. 时间吸附与网格

吸附粒度按**拍**算，和 Arcaea 编辑器一致：

| 选项 | 等于多少拍 |
| --- | --- |
| OFF | 不吸附（仍取整毫秒） |
| 1/16 | 1/4 拍（4 格 / 拍） |
| 1/12 | 1/3 拍（三连音） |
| 1/8 | 1/2 拍 |
| 1/6 | 2/3 拍（三连音） |
| 1/4 | 1 拍 |
| 1/3 | 4/3 拍（三连音，3 个占一小节） |
| 1/2 | 2 拍 |
| 1/1 | 4 拍（一小节） |

- 网格基于 `timing` 的 BPM / 每小节拍数；有多个 timing 点时按所在段计算。
- 拖动、放置、播放头移动、shift / SV 点的时间都用同一个吸附函数。
- 显示：小节线较亮，拍线次之，细分线更暗；细分间距小于 7px 时自动不画。
- 150 BPM 下一拍 400ms：`1/8` = 200ms，正好是内置验收谱的网格。

## 6. 音频、offset 与波形

右侧 `AUDIO`：

- **TRACK**：选择本地音频（也支持把音频文件拖进页面）。解码后：
  - 波形画在标尺下面的波形带里；
  - 预览播放会用它当音轨（1× 正放时）；
  - 找不到文件 / 解码失败会在 `VALIDATION` 上方显示错误。
- **OFFSET (ms)**：就是 `meta.offset`，和游戏设置里的 AUDIO OFFSET 同一语义：
  **正值 = 谱面时间比音频提前**。波形会跟着左右平移：
  谱面时间 `t` 处画的是音频 `t − offset` 的采样。
  用 `−10 / −1 / +1 / +10` 微调，把鼓点 / 人声对齐到小节线。
- 没有音频时，预览按 `timing` 现场合成鼓点，照样能对拍。
- 音量 / 节拍器只影响预览，不写进谱面。

> 音频文件不会保存进 JSON / localStorage。导出的谱面只记 `audio` 文件名，
> 游戏里需要 `?audio=/你的音频.mp3` 或把文件放到 `public/`。

## 7. 存档 / 导出 / 导入

| 动作 | 结果 |
| --- | --- |
| 自动 | 每次改动后 650ms 写 localStorage 草稿；关页面前再写一次 |
| `EXPORT` / `Ctrl+S` | 下载 `<title>.parallax.json` |
| `IMPORT` | 读入这种 JSON（字段缺失会补默认值，然后跑校验） |
| `NEW` | 空谱（有内容时确认） |
| `LOAD TEST / LOAD DEMO` | 载入内置验收谱 / 12 秒示例 |
| `CLEAR DRAFT` | 只删 localStorage 草稿，不动当前编辑内容 |

游戏页读取导出文件：

```bash
# 把导出的 JSON 放进 public/charts/
cp ~/Downloads/xxx.parallax.json prototype/public/charts/
# 打开
http://127.0.0.1:5173/?chart=/charts/xxx.parallax.json
# 有音轨时
http://127.0.0.1:5173/?chart=/charts/xxx.parallax.json&audio=/track.mp3
```

格式与校验都走 `src/chart/schema.ts` / `src/chart/timeline.ts`，和播放器完全同一套。

## 9. 校验与限制

右侧 `VALIDATION` 实时跑 `validateChart`，顶栏同时显示问题数：

- note 的 lane 必须是 0–5 的整数，并且落在**当时的窗口**里；
- arc 至少两个点、首点 time = 0、点时间递增、x ∈ [−0.5, 5.5]、y ≥ 0；
- **arc 最高点 ≤ `limits.maxHeight`（默认 0.81m = 头顶线）**；
- key objects 必须落在弧长内；
- timing / speed / shift 的排序与取值范围；
- notes 建议按时间排序（编辑器每次改动都会自动排序）。

校验只是提示，**不会阻止编辑**；超限的 arc 在播放器里不会生成（和游戏一致）。
高度上限可以在谱面里覆盖：

```jsonc
"limits": { "maxHeight": 0.81 }
```

## 11. 已知限制

- 没有波形缩放 / 频谱；只能用时间轴缩放看波形。
- 没有 BPM 检测 / 自动对齐；BPM 和 offset 手动填。
- 没有多选、复制粘贴、框选；一次一个选区。
- 没有 section 标记编辑（导入时会保留）。
- arc 的中间点插入会继承后一段的缓动，曲线在插入点处可能有很小的形状变化。
- 音频只存在于当前页面会话；刷新 / 换设备后要重新导入。
- 预览的 1× 正放用音频时钟，**慢放 / 倒放是静音的**（AudioContext 不支持倒退）。
- 3D 预览按窗口大小渲染，窄窗口里视野比头显窄；它验证的是谱面，不是视场。

## 12. 做一段谱的推荐流程

1. `AUDIO` 导入音轨；用 offset 把第一个重拍对到 `0:00` 的小节线。
2. 填 `TITLE / DIFFICULTY`，`TIMING` 确认 BPM 和拍数。
3. `SNAP` 选 `1/8`（或更细），先用 HIT 把主旋律 / 鼓点铺一遍。
4. 加 HOLD / ARC；在高度轨把 arc 抬到胸 / 面；用 `KEY OBJECTS` 标关键物量。
5. `SHIFT` 在段落切换处加窗口移动；`SV` 在需要停顿 / 加速的地方加点。
6. 按 `Space` 用 1× 跑一遍，再用 0.5× 看判定与视觉；`REV` 检查后半段。
7. `EXPORT`，把 JSON 放进 `prototype/public/charts/`，用
   `?chart=/charts/…json` 在游戏页 / Quest 里最终验一遍。
