# GRADE LAB — 评级字体 / 数学符号层

> **设计样张，不接游戏状态。** 按 [`DESIGN-WORKFLOW.md`](../../DESIGN-WORKFLOW.md)：
> 先在干净环境里决定“评级长什么样”，再回主代码移植。

## 问题

`FUTURE.md` §0.2：Result 目前没有评级。阈值已经定死在
`<80 D / 80–85 C / 85–90 B / 90–95 A`，但 95% 以上四档“叫什么”一直悬着——
`S / SS / EX / EX+` 这类已经被用滥。

## 结论方向

用户定的路子：**数学同一性符号 + 三字母英文简写**。

- **三个字母是主体**：大字、紧字距、读得出来；
- **数学符号是后层**：放大、压到 ~10% 不透明度，只提供层级的“重量”，不参与阅读。

选数学符号是因为它本身就在表达“有多接近”：`≈` 约等于 → `≃` 渐近 → `≅` 全等 → `≡` 恒等。
它比 S/EX 更贴“准确率”这件事，也不需要玩家认识任何神话或游戏梗。

符号全部是自绘 SVG（不是字体）：

- `≈` 两波
- `≃` 一波 + 一横
- `≅` 一波 + 两横
- `≡` 三横

波纹逐级消失 —— “误差在收敛”这件事直接变成了字形。这样 Quest 上也不会有字体缺字的问题。

## 现在的档位

| 评级 | 区间 | 后层符号 | 词源 |
| --- | --- | --- | --- |
| `D` | < 80% | — | — |
| `C` | 80–85% | — | — |
| `B` | 85–90% | — | — |
| `A` | 90–95% | — | — |
| `APX` | 95–97% | `≈` | approximate |
| `ASM` | 97–98% | `≃` | asymptotic |
| `CGR` | 98–99% | `≅` | congruent |
| `IDN` | 99–100% | `≡` | identical |

设计上的取舍：

- **95% 以下不加符号**：后层是“超出字母表”的信号，D–A 还在地面上；
- 三个字母用辅音缩写（`APX / ASM / CGR / IDN`），读起来像仪器代码，不像单词；
- 符号永远不单独承担信息：即使看不见符号，`CGR` 也能读出来。

## 没定的部分

- 字母究竟用哪四个词（`APX/ASM/CGR/IDN` 是当前提案，还没锁死）；
- 100% 是否需要单独一个“章”（例如符号从 `≡` 收成一个环）；
- 字体本身：样张用系统字体，真正做的时候要选一款 display 字，或者自绘字形；
- 符号层的动效（呼吸 / 收拢）属于后续，不在这个样张里。

## 怎么看

从仓库根目录起一个静态服务器（不要用 `file://`）：

```bash
python3 -m http.server 8080
# http://127.0.0.1:8080/design/grade-lab/
```

页面上的两个按钮：

- **符号层**：开 / 关后层，检查“没有符号时评级是否仍然成立”；
- **阈值**：暂时没有绑定（预留给后续的阈值/档位切换）。

## 验收

- 760×470 逻辑画布、1.35m 观看距离下，评级 1 秒内可读；
- 后层符号不抢字；
- 去掉符号层后仍然认得出档位；
- 与 tier 主题色不冲突（评级本身不用 tier 色）。
